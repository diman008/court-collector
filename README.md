# Judicial Intelligence (реинжиниринг KAD + Court Collector)

**Статус:** v2.4.0-alpha.1 — безопасный MVP для ручного импорта судебных текстов; не готов к публичному production.

Цель: воспроизводимый анализ судебных материалов с доказательствами, точной цитатой,
документом-источником и датой. Система НЕ решает, было ли нарушение: окончательные
юридические выводы делает эксперт после проверки первоисточников.

## Что уже есть

- Единый формат номеров арбитражных дел (А40-12345/2025), нормализация и поиск по локальной базе.
- Импорт UTF-8 TXT через CLI, приём текста через API, сохранение SHA-256, источник, дата и
  исключение повторных документов в пределах дела.
- Выделение **дословных** упоминаний статей НК РФ с посимвольными смещениями.
- API с обязательным `X-API-Key`; при отсутствующем ключе закрыт, кроме /health.
- SQLite MVP, автоматические тесты и проверка Docker-сборки в PR.
- Не делает сетевых запросов к судебным сайтам, СПАРК или закрытым системам.

## Быстрый старт

Python 3.11+:

```bash
python -m pip install -e ".[test]"
python -m pytest -q
python -m judicial_intelligence.cli --db data/local.db add-case А40-12345/2025 --court "Арбитражный суд"
python -m judicial_intelligence.cli --db data/local.db import-txt А40-12345/2025 ./decision.txt --source-url https://example.org/decision
python -m judicial_intelligence.cli --db data/local.db report А40-12345/2025
```

Локальный API (НЕ публикуйте в интернет без TLS, внешнего контроля доступа и защиты данных):

```bash
export JUDICIAL_API_KEY="replace-with-a-long-random-secret"
export JUDICIAL_DB_PATH="data/judicial.sqlite3"
uvicorn judicial_intelligence.api:app --host 127.0.0.1 --port 8000
```

- `POST /v1/cases`: `{"case_number":"А40-12345/2025"}`
- `POST /v1/documents?case_number={number}`: `{"text":"...","source_kind":"user_provided"}`
- `GET /v1/cases?q=...`: локальный поиск
- `GET /v1/case?case_number={number}`: получить карточку
- `GET /v1/documents?case_number={number}`: метаданные документов
- `GET /v1/report?case_number={number}`: цитаты, offsets, SHA-256, пределы выводов
- `GET /health`: статус сервиса, без доступа к данным

## Границы и история

- `kad` (2025): FastAPI-прокси к недокументированному маршруту КАД с ScraperAPI fallback.
  Этот механизм **не входит** в v2: поддержка, правила доступа и стабильность не подтверждены.
- `court-collector` (2025): шаблон FastAPI/OpenAPI/Playwright без полноценных задач сбора.
  В v2 API переписан и работает; прежние `/start`, `/status`, `/download` не сохраняются.
- Исходный код остаётся в истории Git и в оригинальном репозитории kad до отдельной архивации.
- См. [стратегию](docs/STRATEGY.md), [план миграции](docs/MIGRATION.md) и [безопасность](docs/SECURITY.md).

Ключевой принцип: **лучше честно пометить отсутствие источника, чем выдать фиктивный факт.**

## v2.1 alpha: PDF/DOCX, цепочка доказательств, хронология суда

Из исходных судебных документов теперь можно строить проверяемый слой ссылок на нормы:

- PDF: офлайн-извлечение текста, физические номера страниц исходного PDF и позиции цитат.
- DOCX: офлайн-извлечение текста, **логический сегмент** вместо вымышленных номеров страниц.
- Оригинальные байты и SHA-256 сохраняются в локальной SQLite, повторные файлы распознаются.
- Статус любых загруженных актов: unverified_user_input; электронная подпись не проверяется.
- История судебных актов хранит суд, инстанцию, дату, связь с предшествующим актом и источник.
- Исторические версии правовых норм доступны по дате; источник/применимость требуют экспертизы.
- По умолчанию OCR отключён; дополнительный локальный OCR для сканированных страниц запускается вручную флагом `--ocr`.
- Файлы: не более 8 MiB; до 200 страниц и 200000 извлечённых символов.

### Офлайн-команды

1. Создать карточку: judicial-intelligence add-case А40-12345/2025
2. Импорт: judicial-intelligence import-file А40-12345/2025 ./court.pdf
3. Извлечённые упоминания: judicial-intelligence evidence-report А40-12345/2025
4. Хронология: judicial-intelligence timeline А40-12345/2025

### Защищённое API

- POST /v1/evidence-files — multipart upload с case_number, file, source_kind, source_url.
- GET /v1/evidence-files?case_number=... — метаданные и хеши исходников.
- GET /v1/evidence-report?case_number=... — точные цитаты и страница/сегмент.
- POST /v1/acts — метаданные судебного акта и связи с предыдущими актами.
- GET /v1/timeline?case_number=... — хронология, **не** доказательство вступления решения в силу.
- POST /v1/norms, GET /v1/norms?norm_id=...&on_date=... — версии текста правовой нормы.

Все эти API требуют X-API-Key. Это **локальный опытный сервис**, не публичная production-система.
Для дальнейшей архитектуры см. docs/SOURCE-REGISTRY.md и docs/STRATEGY.md.

## v2.2 alpha: офлайн-OCR и приватный MCP

**Локальный OCR (по явному выбору):**

```bash
python -m pip install -e ".[ocr]"
# Установите локальный Tesseract и языковые модели rus и eng.
judicial-intelligence import-file А40-12345/2025 ./scan.pdf --ocr
```

Не поддерживается массовый OCR без лимитов. Максимум 12 пустых текстовых страниц
за один документ, время распознавания ограничено; нужна проверка человеком.
Отрывки с OCR имеют признак `ocr_page`; координаты символов относятся к
**распознанному тексту**, а не к пикселям оригинала.

**Приватный MCP — только для локального использования:**

```bash
python -m pip install -e ".[mcp]"
export JUDICIAL_DB_PATH="data/judicial.sqlite3"
export JUDICIAL_MCP_KEY="replace-with-a-random-32-or-more-character-secret"
python -m judicial_intelligence.private_mcp
```

Сервер слушает **только 127.0.0.1:8765**, транспорт Streamable HTTP,
`X-API-Key` обязателен. В MCP доступны только чтение локальных дел, их
истории, ссылок на правовые нормы и инструкции по ручной проверке ЭП.
Текущая версия **не является коннектором ChatGPT**: для удалённого подключения
нужны поддерживаемая авторизация/OAuth, TLS, допустимое размещение документов,
журналирование и отдельное согласование безопасности. Не публикуйте порт в интернет.

Порядок проверки официальной электронной подписи — [VERIFICATION](docs/VERIFICATION.md).

- GET /v1/verification-packet?case_number=...&file_id=... — контроль SHA-256 сохранённого оригинала и пошаговый порядок независимой проверки, **без** автоматического утверждения подлинности.
- MCP tool local_verification_packet — такой же read-only контроль для доверенного локального агента.

## v2.3 alpha: локальное рабочее место аналитика

После локального запуска FastAPI откройте **http://127.0.0.1:8000/analyst**.

Нужно ввести `JUDICIAL_API_KEY` в форму. Приложение не сохраняет
ключ в `localStorage`, `sessionStorage` или файлы и использует только
текущий JavaScript-сеанс вкладки.

Возможности:
- Поиск и создание локальных карточек судебных дел.
- Импорт PDF/DOCX, просмотр источников и SHA-256.
- Сводка `GET /v1/dossier?case_number=...`: история, упоминания,
  непроверенные сведения и ссылки на конкретный файл/страницу/смещение.
- Ручная проверка целостности каждого вложения по `/v1/verification-packet`.
- Журнал ручных проверок `POST /v1/reviews` и `GET /v1/reviews`,
  с точным доменом официального источника, псевдонимом проверяющего,
  исходом и связью с локальным файлом.
- Все журнальные отметки имеют признак `independent_verification=not_performed`:
  даже запись «совпадает» НЕ подтверждает ЭП и юридический статус акта.
- Адаптивная страница для телефона и компьютера без внешних JS/CSS/CDN.

**Важное ограничение:** это только локальный однопользовательский
прототип на SQLite. Не предоставляйте ссылку на него в интернет.
Не загружайте налоговую тайну и иные ограниченные сведения,
пока не реализованы утверждённые правила доступа, хранения и аудита.

Принципы переиспользования библиотек и каталога «Ресурсы инспектора» —
[REUSE-DECISIONS](docs/REUSE-DECISIONS.md).


### Приватный MCP и интерфейс используют одну локальную базу

Приватный MCP (уже в составе пакета) теперь предоставляет восемь инструментов
только для чтения. Добавлены `analyst_case_dossier` и
`manual_source_review_log` — ограниченные результаты той же базы, что
отображается в интерфейсе. Никакого автоматического обращения к КАД нет.

### Приоритеты после v2.3

1. Проверить реальные примеры документов на точность извлечения текста и OCR.
2. Создать изолированный сервер/воркер, секреты и защищённую БД в согласованном контуре.
3. Проработать идентификацию сотрудников и роли; единый API-ключ нельзя использовать как многопользовательскую авторизацию.
4. Согласовать право на программный доступ к государственным и коммерческим источникам.
5. Только затем подключать полнофункциональный MCP ChatGPT через поддерживаемый TLS/OAuth.

## v2.4 alpha: полнотекстовый поиск и сравнение судебных дел

В уже существующем локальном интерфейсе `/analyst` появились:
1. Поиск слов и фраз по импортированным судебным документам с источником,
   номером страницы (если подтверждён парсером) и SHA-256 оригинала.
2. Сопоставление двух дел по упомянутым нормам НК РФ, цитатам и **заявленным**
   исходам актов одной инстанции (без автоматического юридического вывода).

Для запросов из командной строки:
```bash
judicial-intelligence fulltext "доказательства поставки" --court Москва
judicial-intelligence compare А40-123/2025 А55-456/2025
```

Через авторизованный API: `GET /v1/fulltext` и `GET /v1/compare`.
В приватном локальном MCP добавлены инструменты
`search_imported_court_text` и `compare_imported_cases`.
Результаты находятся **только** среди документов локальной базы;
ни КАД, ни СПАРК по этим запросам автоматически не опрашиваются.
Входные данные и выводы остаются непроверенными до контроля первоисточника.

**Пилот Docling** включается отдельно и не нужен для обычной работы.
Для него требуется установить дополнительные зависимости и модели;
конвертация должна запускаться в изолированной среде и
`HF_HUB_OFFLINE=1` — без автоматической выгрузки файлов на внешние сайты.
Тесты пилотного адаптера используют подставной конвертер, а не реальный
бенчмарк распознавания сложных судебных PDF.

Описание и ограничения: [V24-SEARCH-AND-DOCLING](docs/V24-SEARCH-AND-DOCLING.md).
